# PCM v3 / v4 Neuromorphic Profile

**Status**: Spec sheet for hardware engineers, May 2026.
Companion to `docs/PCM_V3_DUAL_PROCESS_DESIGN.md` and
`docs/PCM_V4_PHYSICS_COOK_DESIGN.md`. Validated by F58
profile script `scripts/neuromorphic_profile.py`.

---

## 1. Why this document exists

PCM's dual-process architecture (System 1 retrieval + System 2
procedural sequencing) is structurally identical to the
**Dual Memory Pathway (DMP)** silicon architectures published
in the 2025–2026 neuromorphic literature:

> *Algorithm-hardware co-design of neuromorphic networks with
> dual memory pathways* (arxiv 2512.07602, ICLR 2026)
>
> "DMP architectures combine fast spiking activity with an
> explicit slow memory pathway, where each layer maintains a
> compact low-dimensional state that summarises recent activity
> and modulates spiking dynamics. … 4× throughput increase and
> 5× energy efficiency improvements."

> *Modern Neuromorphic AI: From Intra-Token to Inter-Token
> Processing* (arxiv 2601.00245, January 2026)
>
> "intra-token processing using spiking neural networks vs
> inter-token processing using state-space dynamics or sparse
> attention."

> *Distributed representations enable robust multi-timescale
> symbolic computation in neuromorphic hardware* (IOPscience
> 2025, validated on Loihi 2)
>
> "Finite state machines can be embedded into RSNN dynamics
> without parameter fine-tuning."

PCM v3's `IterativeDiffCook` is literally a finite state
machine (cursor + step transitions). PCM v4's `PhysicsCook` is
the same but on continuous state. PCM v3's
`RelativePositionEmbedding` is a content-addressable lookup,
the canonical fast pathway. **The DMP / Loihi 2 / Akida silicon
people are building exactly the hardware PCM v3 / v4 needs.**

This document gives them a per-operation spec sheet (§4 below)
plus a per-platform mapping sketch (§5) so the conversation
can start with concrete numbers.

## 2. The four PCM operations to profile

| op | role | hardware analogue |
| --- | --- | --- |
| `RelativePositionEmbedding` lookup + classifier | System 1 retrieval | Content-addressable memory + small dense MLP |
| `SuccessorHead` (one step) | System 2 atomic transition | Single Loihi 2 neuro-core (~131 neurons) |
| `IterativeDiffCook` (K iterations) | System 2 full procedural sequence | RSNN reservoir loop, K ticks |
| `PhysicsStateHead` + `PhysicsCook` (v4) | Continuous-state rollout | Same RSNN reservoir, rate-coded inputs |

Each operation has a different cost profile; the route_diff
dispatcher (F54) picks the cheaper one per query.

## 3. Per-platform mapping

### 3.1 Intel Loihi 2

* **128 neuro-cores per chip**, 1024 neurons each → 131 K neurons
  total. Native ReLU + sigmoid activation; programmable plasticity.
* **1 MB SRAM per chip** for synapses. PCM v3 SuccessorHead is
  ~7 K params → fits in a single core's local memory.
* **Tick rate**: 1 kHz. Each cook iteration costs 1 tick →
  K=99 cook costs ≈ 99 ms per query (1.0 second budget per
  100 queries).
* **Spike encoding**: rate or temporal coding for the slot
  embeddings; classifier output decoded by argmax over rate.

### 3.2 BrainChip Akida

* **Native event-based** + reservoir-style iterative loops in
  hardware. The cook architecture maps directly to a recurrent
  Akida block.
* **Power**: ≤ 5 mW per inference for typical LSTM-equivalent
  networks. PCM cook is smaller (7 K params vs typical 100 K),
  so power should be ≤ 1 mW.

### 3.3 SpiNNaker 2

* **Million-core ARM cluster** with custom DMA. Less power-
  efficient than Loihi 2 but easier to deploy.
* PCM dispatcher (route_diff) maps cleanly because it is
  branching control flow, which SpiNNaker handles well.

### 3.4 FPGA (Xilinx Versal AI Edge)

* Sinusoidal RPE (F55) is the right choice here: no lookup
  memory needed, basis computed at line rate. F58 profile shows
  Sinusoidal RPE has **lookup memory = 0** but FLOPs ≈ 2× the
  classifier alone.

## 4. F58 spec sheet (per query, single batch element)

Generated by `python -m scripts.neuromorphic_profile
--slot-dim 16 --attr-dim 8 --n-cells 100 --K-rollout 99`.

| operation | params | FLOPs | resident KB | I/O bytes |
| --- | ---: | ---: | ---: | ---: |
| **RPE lookup + classifier** (System 1) | 17 207 | 27 584 | 67.2 | 800 |
| **SuccessorHead** (single iter) | 7 491 | 14 848 | 29.3 | 204 |
| **IterativeDiffCook (K=99)** | 7 491 | **1 470 051** | 29.3 | 204 |
| **PhysicsStateHead** (single iter) | 4 482 | 8 832 | 17.5 | 16 |
| **PhysicsCook K=99** | 4 482 | 874 566 | 17.5 | 800 |
| **Sinusoidal RPE + classifier** (F55) | 29 895 | 59 328 | 116.8 | 800 |

### 4.1 Headline tradeoffs

* **Cook is 53× more FLOPs than RPE per query** but **2.3× less
  memory** (7.5 K params vs 17.2 K). On memory-constrained
  silicon (Loihi 2: 1 MB / chip; Akida: ~256 KB SRAM per
  reservoir block), cook is the right choice.
* **Sinusoidal RPE has no lookup memory** but burns 2× the
  classifier FLOPs computing the basis on the fly. Right call
  on FPGAs (compute is cheap, BRAM is precious).
* **PhysicsCook is half the FLOPs of IterativeDiffCook** at the
  same K because the state head is smaller (state_dim=2 vs
  slot_dim=16 + attr_dim=8 = 24).

### 4.2 Combined dispatcher (route_diff F54)

| query type | route | cost |
| --- | --- | --- |
| in-range (|Δ| ≤ train_max) | RPE | 27 584 FLOPs |
| OOD (|Δ| > train_max) | Cook | 1 470 051 FLOPs |
| post-distill (F53) — RPE coverage = full domain | RPE | 27 584 FLOPs |

**Power amortisation**: after F53 sleep distillation expands
RPE coverage and F54 adaptive routing surfaces the new
threshold, **all queries fall onto the cheap RPE path**. Cook
is only invoked when the model encounters genuinely novel
displacement — the exact mature-physicist behaviour the
neuro-imaging literature (Springer 2025; Nat Commun 2024 7T)
documents in human arithmetic.

This is **PCM v3's competitive advantage on neuromorphic
silicon**: an architecture that *learns to be cheap* via
sleep consolidation, not just an architecture that is
constant-time-cheap.

## 5. Loihi 2 reference deployment sketch

```
┌─────────────────────────────────────────────────────┐
│  Loihi 2 chip (128 cores × 1024 neurons = 131 K)    │
├─────────────────────────────────────────────────────┤
│  Core 0–7 (8K neurons)                              │
│    SuccessorHead (slot + attr → step)               │
│    7 491 params, fits in 1 core; replicated         │
│    8× for batch-parallel cook queries.              │
├─────────────────────────────────────────────────────┤
│  Core 8–15 (8K neurons)                             │
│    PhysicsStateHead (state + force → Δstate)        │
│    4 482 params, easily fits.                       │
├─────────────────────────────────────────────────────┤
│  Core 16–47 (32K neurons)                           │
│    RelativePositionEmbedding table                  │
│    For n_cells=100 / embed_dim=16, table is         │
│    199 × 16 = 3 184 entries; classifier is          │
│    Linear(16, 64) + Linear(64, 199).                │
├─────────────────────────────────────────────────────┤
│  Core 48–55 (8K neurons)                            │
│    Adaptive routing (calibrate_rpe_coverage F54)    │
│    Small comparator + threshold; ~50 neurons.       │
├─────────────────────────────────────────────────────┤
│  Core 56+ (free)                                    │
│    Reserved for sleep replay (F53) and additional   │
│    domain heads (colour, space, phoneme).           │
└─────────────────────────────────────────────────────┘
```

Estimated wall-clock per query (1 kHz tick rate):

| query | ticks | wall (ms) |
| --- | ---: | ---: |
| RPE lookup | 1 | 1.0 |
| Cook (K=99) | 99 | 99.0 |
| Sleep distill (F53) cycle | 400 × 1 | 400 |
| Adaptive routing (F54) calibration | ~3 K | 3 |

A cold-start Cook query is ~99 ms; after F53 distillation +
F54 routing all in-range queries fall to 1 ms. **The 100×
speedup mirrors the human acquisition trajectory: novice
arithmetic is slow (counting), expert arithmetic is fast
(retrieval).**

## 6. Falsifiable predictions (for hardware experiments)

* **N1 — DMP-on-Loihi-2 deployment**: a faithful spike-coded
  port of PCM v3 should achieve ≥ 4× throughput vs an ANN
  baseline on the F51 number domain (matching the DMP 2025
  benchmark gain).
* **N2 — Energy per inference**: F58 numbers predict ≤ 100 µJ
  per cook query on Loihi 2 at K=99. An actual silicon run
  should land within ±2× of this estimate.
* **N3 — Adaptive routing speedup**: post-F53/F54 adaptive
  routing should drop average query latency by ~50× (cook
  queries fall to RPE queries in 50% of test cases per F54
  empirical results — 0.557 → 0.000 cook fraction means 100%
  of queries route to RPE post-calibration).

These predictions are **the engineering bridge** between the
software-level PCM v3 / v4 architecture and the silicon
deployments DMP / Loihi 2 are building today.

---

## 7. What this is *not*

* Not a complete VLSI design. The cores-per-operation breakdown
  in §5 is sketch-level; an actual Loihi 2 deployment needs
  Lava/NxSDK-specific compilation passes.
* Not a benchmark of PCM vs SOTA neuromorphic models. The point
  is to quantify the dispatcher (route_diff) advantage and the
  sleep-distillation amortisation, not to claim PCM beats
  current Loihi 2 benchmarks (it doesn't, on tasks Loihi 2 was
  designed for).
* Not a power claim on hardware not yet sampled. Numbers in §3.2
  for Akida are extrapolated from public Akida 2 datasheets;
  PCM-specific power profiles would need actual silicon
  characterisation.

## 8. Reproducibility

```bash
python -m scripts.neuromorphic_profile \
    --slot-dim 16 --attr-dim 8 --n-cells 100 \
    --K-rollout 99 --state-dim 2 \
    --out outputs/f58_profile
```

All numbers in §4 above are deterministic given the parameters;
the script recomputes them from the actual `pcm.dual_channel`,
`pcm.dual_process`, and `pcm.physics` modules, so changes in
those modules will reflect automatically. `outputs/f58_profile/
summary.json` is the JSON snapshot suitable for downstream
hardware-co-design tooling.
